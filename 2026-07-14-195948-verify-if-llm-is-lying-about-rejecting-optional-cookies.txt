  other than browser agent's own report or verdict?                             

  Read 1 file (ctrl+o to expand)

⏺ For a browser_use agent that's supposed to reject optional cookies on
  force.com, here's how to check ground truth independent of the LLM's
  self-reported summary:

  1. Inspect the HAR file you're already saving
  har_file.har captures actual network traffic — look at Set-Cookie response
  headers and Cookie headers on subsequent requests. This tells you what the
  server actually set and what the browser actually sent back, regardless of
  what the agent claims it clicked.

  2. Query the browser's real cookie jar via Playwright, not the agent
  browser_use.Browser wraps Playwright under the hood. After (or during) the
  run, call the underlying context directly:
  context = await browser.get_playwright_context()  # or similar accessor
  cookies = await context.cookies()
  This is deterministic — it reads what the browser engine actually stored,
  bypassing the LLM entirely.

  3. Decode the Consent Management Platform's own state, not just cookie 
  presence
  Most consent banners (OneTrust, Cookiebot, TrustArc, IAB TCF-based ones) don't
  just set/unset arbitrary cookies — they set one structured cookie or
  localStorage value encoding exactly which categories were accepted:
  - OneTrust: OptanonConsent cookie (contains groups=C0001:1,C0002:0,...)
  - Cookiebot: CookieConsent cookie (JSON with per-category booleans)
  - IAB TCF: __tcfapi('getTCData', ...) returns a machine-readable consent
  string

  Parsing this string is far more reliable than trusting "I rejected optional
  cookies" from the agent, since it tells you the platform's own recorded
  decision.

  4. Diff third-party network calls before vs. after the consent action
  If optional/tracking cookies were genuinely rejected, requests to analytics/ad
  endpoints (Google Analytics, Facebook Pixel, etc.) should be absent or
  reduced in the HAR after the decision point. Presence of those calls
  post-rejection is strong evidence the "reject" didn't actually take effect
  server-side, even if the UI looked right.

  5. Snapshot the banner's DOM/toggle state at the moment of dismissal
  Capture the accessibility tree or raw DOM of the consent widget right before
  it clicks "confirm" — toggle states (aria-checked, checkbox checked attribute)
  are structural evidence of what was selected, independent of the agent's
  narrated reasoning.

  6. Run a separate deterministic verification pass
  After the LLM agent finishes, run a plain (non-LLM) Playwright script against
  the same site/session that reads document.cookie, context.cookies(), and the
  CMP's exposed API. Treat this as your ground-truth oracle and diff it against
  the agent's stated actions — this is the standard pattern for evaluating agent
  trustworthiness (verify with a dumb, deterministic checker rather than
  trusting the actor's own account).

  If you want, I can wire #2/#3/#6 into agent.py as a post-run verification step
  that cross-checks the agent's summary against actual cookie/CMP state.
